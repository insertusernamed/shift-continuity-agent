Human decision boundary

Only a human may decide or reopen.

Deciding a conflict and reopening a decision are human actions. The system never takes either on its own, and the model cannot approve its own request.

Both tools refuse unless the current request names the item and the choice. That authorization is detected deterministically before the model runs, and the tool re-checks it — so the gate is model-independent by construction.

Who acted and why come from the application context, never from the model: reopen_human_decision takes no actor argument at all.

✓ Explicit request: item + choice → appended

✕ Anything else → refused, nothing written

What the model cannot do

  • Invent current state — it has to call get_shift_state.
  • Decide a conflict, or reopen a decision.
  • Fabricate authority, an actor, or a reason.

Who owns what

ModelInterprets one sentence. Chooses a tool. Nothing else.
DomainValidates, appends, folds, gates authority, builds the handoff.
StorageKeeps the events. Never a second truth.

A refusal is not a failure: the item stays conflicted, and it stays in the handoff until a human settles it.

One implementation, two hosts

Local app the operator UI and HTTP API — src/main.ts
AgentCore runtime the same agent over /invocations — app/ShiftContinuityAgent

The runtime entrypoint is a thin adapter: parse the request, hydrate the store, invoke the agent, return the reply with its tool trace. There is no second copy of the agent, the fold, or the gate.
